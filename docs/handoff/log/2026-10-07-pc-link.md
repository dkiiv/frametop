# 2026-10-07 — PC link: heartbeat, monitor arrangement, physical-monitor fail-safe (observe mode tested)

Curtis's requirements (2026-10-07):
1. While the Frame shows virtual monitors, the PC's physical monitors go "disconnected", so every
   window is reachable from the Frame.
2. A Windows-side runtime listens for a heartbeat that the Frame sends only while one of its
   virtual monitors is open; without it, Windows takes the physical displays back and turns the
   virtual ones off (the PC must never be left unusable if the Frame disconnects/crashes/exits).
3. The Frame sends how its virtual screens sit relative to each other, and Windows arranges its
   monitors the same way (left panel = left monitor), so dragging windows across is natural.
4. Coordinate the first real test of the physical disconnect with Curtis.

Done:
- remote-display/host/ftrd-host.ps1 (Windows agent; README there) and
  remote-display/stream/ftrd-presence.py (Frame responder, started by stream.sh). The PC pings
  the Frame (outbound UDP 47810, so no Windows firewall rule or admin needed); the Frame answers
  only while an instance runs; replies are HMAC-signed with a shared key over the PC's nonce.
- ftrd-stream writes its state (size, app, identity, window id, suspended) to FTRD_STATE_FILE.
- ft-floatd: `list apps` (output:ft-screens number:app) so the Frame knows which panel holds
  which monitor; panel azimuth/elevation from ft-screens "get N" and "head". Needs ft-floatd
  restarted (next desktop restart) to take effect; until then monitors are a row in instance
  order.
- Observe mode (default) replaces the earlier layout watcher: physical monitors kept at the saved
  baseline, virtual monitors arranged right of them. Control mode (physical off) is coded,
  untested, and off until Curtis and I test it together.
- Fail-safe paths: Frame silent 5 s or reporting no monitors -> physical back at the baseline
  (+ Vibepollo terminate_virtual with an optional API token); a guard process restores if the
  agent dies while armed; the agent restores at startup if it finds itself armed.
- ftrd-stream: also retries when the host says another stream operation is still running.

Measured:
- Link: Frame answered with 2 monitors (cert hash, size); the agent mapped both to Vibepollo's
  displays and arranged them right of the ultrawide (5120,0 and 6688,0) with the physical layout
  untouched.
- Frame silent (presence killed at 19:50:00): agent logged "Frame silent for 5 s" and ran the
  restore at 19:50:06-07.

Next (with Curtis, coordinated): control mode. Plan: Curtis at the PC; enable with `control.on`;
float one monitor; expect the physical monitors to go dark and the virtual one to become primary;
then kill the Frame side (stream.sh off) and expect the physical monitors back within ~6 s. Abort:
Win+P -> Extend, or delete control.on.

## Update 20:25: first worn try, fixes (crash on move, blinking, leftover screen)

Curtis: "Remote PC (all monitors)" opened both, then one crashed when he moved a panel; screens
blinked as soon as he touched a panel; after closing both, Windows still had "screen 3".

Found:
- The "crash": monitor 1's window was sized to its panel (1568x1237) a second after it started,
  so --follow-size reconnected; Vibepollo then failed the new size 3x ("not yet capture-ready",
  "topology did not apply"), each attempt re-jogging the whole display topology (the blinking),
  and ftrd-stream gave up and exited. Our agent re-applying the layout in between made it worse.
- The panel azimuths were head-relative, so they changed whenever Curtis turned his head; the
  agent re-applied whenever anything differed, with full mode sets on the physical monitors.
- Screen 3: Vibepollo's deferred-cleanup leftover again (its log: "Deferring virtual display
  cleanup until the remaining managed client display sessions release ownership").

Fixed:
- ftrd-stream maps its window at once with a dark placeholder, waits for the panel's size, and
  starts the monitor at it (no reconnect at open: verified, "window: 1568x1237 after 1.5 s;
  monitor starts at 1568x1232"). A failed reconnect keeps the window and retries after 5/10/15 s
  (6 tries) instead of exiting; Vibepollo retries back off (3 s, 6 s) instead of 2 s x3.
- ftrd-stream reports "busy" while (re)starting; the agent leaves Windows alone then.
- Agent: arrangement = column order of the panels relative to their mean direction (head turns
  don't matter); a new order is taken after the panels stood still 4 s, and only with >= 8 deg
  between neighbours; Windows is touched only after its displays were stable 5 s, 8 s after our
  last change, and only for what differs (position only unless a physical mode is off). Virtual
  monitors the Frame didn't name are never moved.
- Leftovers: optional Vibepollo API token -> terminate_virtual after the Frame said "no monitors"
  for 30 s; `stream.sh cleanup` cleared this one.

Verified headless: float-all -> 1 at 5120,0 (1568x1232), 2 at 6688,0; one layout change, after
settling. Worn test of moving panels pending.
