## Update 23:00: lowest friction (one line per device, pairing without typing)

Curtis: "do whatever is needed to make this as low friction as possible for new users".
- PC: `irm .../remote-display/host/install.ps1 | iex` -> ftrd-host.ps1 -Install: Vibepollo 2.0.0
  downloaded, SHA-256 checked, installed with /quiet (one UAC prompt); a web login made through
  Vibepollo's first-run /api/password (or the user's existing one asked once); a scoped API token
  (pin, clients list/update, terminate_virtual) kept with DPAPI; helper at logon; pairing open 30 min.
- Frame: `curl .../remote-display/get.sh | bash` -> clone the branch to ~/frametop, install.sh,
  which now also builds Remote PC and adds the menu entry. "Remote PC" runs setup in Konsole the
  first time (finds the PC, pairs N monitors), then floats them.
- Pairing without typing: setup writes pairing.json; ftrd-presence answers the helper's ping with
  FTRD2-PAIR {name, pin}; the helper posts it to /api/pin (automatically inside the window,
  else after a Yes dialog) and grants list/view/launch + mouse/keyboard/controller.
- Uninstall: ftrd-host -Uninstall [-RemoveVibepollo]; Frametop's uninstall.sh also removes
  Remote PC's menu entries, cache and (with the settings) its pairings.

## Update 23:45: Curtis's walk-through, first snag

The PC one-liner stopped at "Vibepollo already has a login" -> Unauthorized. Cause (mine): silent
installs go to Program Files\Apollo (the interactive one had gone over Sunshine's folder), and
the helper and its uninstaller only knew Program Files\Sunshine. So the teardown left Apollo\config
(my test's generated login and pairings) and the reinstall picked it up. The same wrong path broke
the helper's check of the Frame's signed answers (arrangement): the earlier "signed by a device
Vibepollo hasn't paired" lines were this, not a stale key.
Fixed: Vibepollo-Dir (uninstall entry / service / known folders) for the config path; -Install
offers Cancel -> reset the login (sunshine.exe --creds, one UAC prompt); -Uninstall removes both
folders.
