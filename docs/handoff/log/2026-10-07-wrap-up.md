Done:
- remote-display/README.md: the user guide (what you need, set up once on the PC and the Frame,
  use, troubleshooting, limits). host/README.md rewritten for the current agent.
- `stream.sh setup [PC address] [monitors]`: builds if needed, saves the PC address
  (~/.config/frametop-remote-display/host, used by every command), pairs each monitor with a
  generated PIN (skips already-paired ones: `ftrd-stream --check`), reminds about Vibepollo's
  per-device permissions, installs the single "Remote PC" menu entry. Paths come from the
  checkout (new users have ~/frametop, not ~/dev/frametop).
- PC link without a shared key: ftrd-presence signs (RSA-SHA256, openssl) with identity 1's
  pairing key; ftrd-host verifies against the certificate in Vibepollo's sunshine_state.json.
  The PC finds the Frame by directed broadcast and remembers it. Verified: "Frame found at
  10.35.78.1", answer accepted.
- `ftrd-host.ps1 -Install/-Uninstall` (copies itself to %LOCALAPPDATA%\ftrd, saves the layout,
  Startup shortcut, starts). Reinstalled on Curtis's PC that way; old C:\ProgramData\ftrd and the
  link key removed.

- 04-milestones: M0-M3 boxes ticked (done in their sessions), status line, M5 lasers item, M6.

Broke / fixed (important):
- My first `setup` "already paired?" check ran `ftrd-stream --app-id 0`, which Vibepollo treats
  as its "Desktop" app; Desktop makes its virtual screen the PC's ONLY display. Curtis's physical
  monitors went dark (20:39, a few minutes). Recovered with the SetDisplayConfig(EXTEND) keeper;
  layout back at 240 Hz. A leftover virtual 5120x1440 screen (DISPLAY33) remained right of the
  ultrawide; needs a Vibepollo service restart (UAC) or the API token.
  Fixes: `--check` (no app started); ftrd-stream refuses "Desktop" and id 0 unless
  FTRD_ALLOW_DESKTOP=1; default app is now "Remote Monitor" (2560x1440); the hidden "Remote PC
  desktop" entry and `float-desktop` are gone.
- `pkill -f ftrd-presence` inside an ssh command matched its own shell twice; use a bracket
  pattern and keep the start in a separate command.
